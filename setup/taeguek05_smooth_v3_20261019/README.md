# 태극 5장 SmoothV3 보상 튜닝 — 2026-10-19

대상: `taeguek_selected_20261019/taeguek_05`의 SupportV2 `model_9999.pt`.
이 폴더의 전용 task만 변경한다. 기존 모션 NPZ/CSV, 관측, action scale, PD 게인,
접촉 모델, 실물 및 sim2sim 설치 정책은 변경하지 않는다.

## 보상 변경

신규 비용은 `min(1, 0.1 + 0.9 * common_step_counter / 24000)`으로 증가한다.
정책 24 step/update이므로 약 1,000 PPO update 후 최종 강도에 도달한다.
모든 기존 tracking reward 및 `action_rate_l2=-0.1`은 유지한다.
아래 비용은 `sqrt(1+x²)-1`, 최대 4로 제한한 robust cost의 관절/축 평균이다.
RewardManager가 전체 reward에 정책 dt=0.02초를 곱한다.

| 항목 | 최종 가중치 | 기준/정규화 |
|---|---:|---|
| 몸통 수평 각속도 오차 | -0.35 | 실제-기준, 0.6 rad/s |
| 위 오차의 시간 변화 | -0.12 | 15 rad/s² |
| 팔 10관절 속도 오차 | -0.20 | 1.5 + 0.25×기준 속도 절댓값 |
| 전 관절 속도 오차의 시간 변화 | -0.08 | 40 + 0.5×기준 가속도 절댓값 |
| 팔 관절 속도 오차의 시간 변화 | -0.08 | 30 + 0.5×기준 가속도 절댓값 |
| 팔 자세 추종 | +0.35 | 관절별 exp(-각도오차²/0.45²)의 평균, 즉시 적용 |
| 느린 발 이동 중 초과 들림 | -0.35 | 아래 조건, 발별 합계 |

- 몸통 항은 world x/y 각속도 오차를 사용한다. 의도한 yaw 회전은 기존 추종 보상이 담당한다.
- 가속도 항은 기준을 뺀 속도 오차의 차분이다. 기준과 같은 빠른 지르기·발차기는 비용이 0이다.
  급격한 기준 동작은 기준 가속도에 따라 허용 척도를 늘린다. 특정 주파수만 제거하는 필터는 아니다.
- 시간 차분은 연속된 기준 프레임에서만 사용하고 리셋/프레임 점프 뒤 0.15초 유예한다.
- 발 보상은 기준 발바닥이 ±40ms 동안 12mm 이하이며 기존 지지/발차기 마스크 밖인 구간에만 적용한다.
  기준 최저 접촉점 XY 속도 v가 0.8m/s 이상이면 비용이 0이다.
  그보다 느리면 높이 허용오차 `3mm + 4mm×v`, 척도 10mm, 가중 배율 `1-v/0.8`을 쓴다.
  실제 발 속도나 접지 여부로 보상 적용을 끄지 않는다.
- 기존 SupportV2의 접촉 유지, 긴 무하중, 재이륙, 미끄럼, 지지발 높이 및 발차기 높이 보상은
  최종 강도로 유지한다. 기존 개선을 다시 약하게 시작하지 않는다.

## 학습 구성

- selected 5장 actor/critic을 정확히 불러오고 optimizer/iteration은 새로 시작한다.
- 원본 SHA256: `e5779c2de5aa1d96367f2a294a55a7419f8f78a50da32b56dc48cf56aefb90f0`.
- 학습률 `1e-4 → 5e-5`, fixed; entropy 0.001 유지.
- 4,096 환경, 총 10,000 추가 update, 250 update마다 저장.
- 40.32초 전 동작을 볼 수 있도록 최대 episode 30 → 42.34초.
- 환경 30%는 첫 프레임에서 시작하고, 나머지는 기존 실패 적응 샘플링에 20% uniform mixture.
- 외란/랜덤화/종료 임계값은 유지한다.
- 재실행하면 이 전용 finetune run의 최신 유효 체크포인트에서 optimizer와 보상 ramp를 복원하고,
  10,000회까지 남은 update만 실행한다. smoke run은 자동 재개 후보에서 제외한다.
- GPU가 사용 중이면 종료하며 기존 프로세스를 중단하지 않는다.

## 검증 및 판정 범위

`test_rewards.py`: 기준과 정확히 같은 빠른 움직임은 비용 0, 추가 진동은 양의 비용,
중복 호출 및 부분 리셋/프레임 점프 처리, 회전/발차기 예외, 원본 task 비변경을 검사한다.
`preflight.py`: 원본 정책으로 32개 GPU 환경에서 2,050 policy step을 실행하여 유한값,
실제 기준 마스크, 전 구간 도달 및 신규 보상 활성화를 검사한다.
`check_smoke.py`: 3회 PPO update 후 actor/critic 유한값, optimizer 상태와 저장 시계 검증.
별도 1회 resume smoke로 재개 기능도 확인한다.

- 동작/리셋 회귀 테스트 4개 통과.
